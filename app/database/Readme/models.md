# Database Models

## 1. Overview

The `models.py` module defines the ORM model structures used by the Nevark AI backend.

It currently contains one database model:

- `Conversation` – Represents a conversation exchange between a user and the AI assistant.

The model uses SQLAlchemy's declarative ORM approach and inherits from the shared `Base` object defined in `app/database/database.py`.

Its purpose is to define how conversation messages and their timestamps are represented in the SQLite database.

## 2. Dependencies

```python
from sqlalchemy import Column
from sqlalchemy import Integer
from sqlalchemy import String
from sqlalchemy import Text
from sqlalchemy import DateTime

from datetime import datetime

from app.database.database import Base
```

| Dependency | Purpose |
|---|---|
| `Column` | Defines individual database table columns |
| `Integer` | Defines integer-based column types |
| `String` | Provides a string column type |
| `Text` | Stores longer text content |
| `DateTime` | Stores date and time values |
| `datetime` | Supplies the default timestamp value |
| `Base` | Provides the shared SQLAlchemy declarative base |

**Note:** `String` is imported but is not currently used in the supplied model.

## 3. Conversation Model

```python
class Conversation(Base):

    __tablename__ = "conversations"
```

The `Conversation` class defines the database structure for storing user-assistant conversation exchanges.

It inherits from `Base`, allowing SQLAlchemy to register the model within the application's ORM metadata.

The table name is explicitly defined as:

`conversations`

### Table structure

The model contains four columns:

| Column | Data type | Constraints | Purpose |
|---|---|---|---|
| `id` | Integer | Primary key, indexed | Unique conversation record identifier |
| `user_message` | Text | Not nullable | Stores the user's message |
| `ai_response` | Text | Not nullable | Stores the AI-generated response |
| `timestamp` | DateTime | Default: `datetime.utcnow` | Stores the conversation timestamp |

## 4. Column Definitions

### 4.1 ID Column

```python
id = Column(
    Integer,
    primary_key=True,
    index=True
)
```

The `id` column uniquely identifies each conversation record.

Configuration:

- `Integer`: Uses an integer data type.
- `primary_key=True`: Defines the column as the table's primary key.
- `index=True`: Requests an index on the column.

This allows individual conversation records to be identified through their primary key.

### 4.2 User Message Column

```python
user_message = Column(
    Text,
    nullable=False
)
```

Stores the message submitted by the user.

Configuration:

- `Text`: Supports longer text content.
- `nullable=False`: Requires a value for this column when inserting a record.

This field preserves the user's original message as part of the conversation exchange.

### 4.3 AI Response Column

```python
ai_response = Column(
    Text,
    nullable=False
)
```

Stores the response generated by the AI assistant.

Configuration:

- `Text`: Supports longer response content.
- `nullable=False`: Requires a value when inserting a record.

Together, `user_message` and `ai_response` represent one conversation exchange.

### 4.4 Timestamp Column

```python
timestamp = Column(
    DateTime,
    default=datetime.utcnow
)
```

Stores the date and time associated with the conversation record.

Configuration:

- `DateTime`: Defines the column as a date-time field.
- `default=datetime.utcnow`: Supplies the current UTC datetime as the default when SQLAlchemy inserts a record without an explicitly supplied timestamp.

The default is a callable, so the datetime is generated when the insert operation requires it rather than when the module is imported.

## 5. Example Database Record

An illustrative conversation record can be represented as:

```json
{
    "id": 1,
    "user_message": "Hello Nevark!",
    "ai_response": "Hey! How can I help you?",
    "timestamp": "2026-11-09T10:30:00"

This example illustrates the logical structure of a record. The actual timestamp depends on when the database record is inserted.

```

This connects the model to the shared SQLAlchemy declarative base.

The database configuration module provides:

- `SessionLocal` – Database session creation.
- `Base` – ORM model registration.

The `Conversation` model uses this shared base to define its table structure.

## 7. Current Implementation Scope

The model currently defines:

- A conversation table named `conversations`.
- An integer primary key.
- A user-message field.
- An AI-response field.
- A timestamp field with a UTC datetime default.
- Non-null constraints for both message fields.
- An index on the primary key.

The model does not currently define:

- User accounts or user IDs.
- Separate conversation or session IDs.
- Foreign-key relationships.
- Message-level records.
- Conversation categories or metadata.
- Message status fields.
- Explicit database relationships.
- Custom validation methods.
- Automatic conversation-history retrieval.

These features are not present in the supplied source.

## 8. Important Implementation Considerations

### 8.1 One record represents one exchange

The table stores the user message and corresponding AI response together in a single row.

It does not store each message as an independent record.

### 8.2 No user-level separation

There is no `user_id` column or other user-identification field in this model.

Consequently, this table structure alone does not provide user-specific conversation separation.

### 8.3 Timestamp behavior

The timestamp default uses `datetime.utcnow`, which produces a naive UTC datetime.

The model does not explicitly configure timezone-aware datetime storage.

### 8.4 Model registration and table creation

Defining the model registers its table structure with SQLAlchemy metadata.

However, this file does not itself create the physical database table. Table creation or migration must be handled elsewhere in the application.

## 9. Summary

The `models.py` module defines the database ORM structure for Nevark AI conversation persistence.

Its `Conversation` model stores each user-assistant exchange in a single database record containing the user message, AI response, unique identifier, and timestamp.

It works alongside `database.py`, which provides the SQLite connection, SQLAlchemy engine, session factory, and declarative base.

Together, these modules establish the foundation for relational conversation storage in the Nevark backend.
